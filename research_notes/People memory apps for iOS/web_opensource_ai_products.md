# People-memory apps outside native iOS and mainstream CRMs: web apps/PWAs, open source, AI wearables, Android, and face-recognition constraints

Status as of 8 November 2026. Scope excludes dedicated native iOS name-memory apps and mainstream personal CRMs (Clay/Dex/Monica), which other researchers cover. "Verified" = read from the cited page; "Inference" = my reading of the evidence. Several GitHub repos could only be inspected through their rendered pages/raw READMEs (the GitHub API was not available in this session), so star counts and dates are as shown on those pages at fetch time.

## Key Question 1: Are there web apps or PWAs that do selfie + name + browse-by-date/category well on iPhone?

### Takeaway
Very little exists. I found no polished, maintained, commercial web app/PWA that combines camera capture of a person you just met, a typed or spoken name, and browsing by name, date and category. The closest things are (a) tiny open-source PWAs with one or zero stars (geetman "Faces", va3un "people-memory"), (b) notes-only web apps without photos (Remember Your People), and (c) name-training web apps that use stock faces (Name Genius, maxeleron). The category is dominated by native iOS/Android apps, and iPhone Safari's home-screen-PWA camera quirks are a plausible reason.

### Cited Findings

**Web apps / PWAs that store people you met (with photo):**
- "Faces" (geetman/Faces-People-Memory-App) is "a mobile-first progressive web app built for the surprisingly large number of people who struggle to remember names, faces, or both"; person cards hold photo, name, nickname, category colour (Family/Friend/Work/Doctor…), tags, "memory hook", 10-second voice memos, an encounter timeline (where/when/what happened each time you saw someone), search by name/nickname, favourites, and a passphrase lock. Photo upload is "from camera or gallery, auto-cropped and compressed to a square". Tech: vanilla HTML/CSS/JS ES modules + Supabase (Postgres with RLS); photos and voice memos stored as base64 text in rows with a ~1 MB row limit. Installs to home screen on iOS via Safari Share > Add to Home Screen; the README does not mention offline caching. Licence CC BY 4.0. Default passphrase `change-me-now` is "stored in plain text in your database and checked client-side". The repo had 1 star and was last updated 2026-06-25 (GitHub search metadata). No hosted demo (placeholder GitHub Pages URL only). — [README](https://raw.githubusercontent.com/geetman/Faces-People-Memory-App/main/README.md); star/update metadata from GitHub search
- "people-memory" (va3un/people-memory) describes itself as "Offline-first people memory app (PWA) for one person. Private, works offline, installs on the phone." Data "stays in your own browser's database"; optional Dropbox sync disabled until configured; optional AI "Smart Capture"/automatic capture off until consent. TypeScript, MIT licence, hosted demo at https://va3un.github.io/people-memory/ ; last pushed 2026-10-29, 0 stars. The README says it is not a 1.0 and recommends "only fictional data until those checks pass". — [README](https://raw.githubusercontent.com/va3un/people-memory/main/README.md)
- The same project's roadmap lists photo capture ("camera or gallery, shrunk before saving"), names/nicknames, notes, a free-text category field, search, offline install + Dexie/IndexedDB, import/export, Dropbox sync and AI capture all as *planned* phases; "browse by date" is not in the v1 plan (browse is by contexts and categories). The only ticked items are Phase 0 (repo + README). — [ROADMAP.md](https://raw.githubusercontent.com/va3un/people-memory/main/docs/ROADMAP.md)
- "Remember Your People!" (remember-your-people.app) is "an end-to-end encrypted web app for taking notes on the people in your life"; free for 5 notes, Premium €12/month for unlimited notes and custom templates; self-hosting offered; Product Hunt listing "Launched in 2026" / "4mo ago" with 7 upvotes. The listing does not mention photos, tags or search. — [Product Hunt](https://www.producthunt.com/products/remember-your-people)
- tordsta/name-remember is an "Example project. Web App for remembering names from face images", Next.js + PostgreSQL + Docker + Terraform on Google Cloud (Cloud Run, Cloud SQL), with Stripe premium tier, Slack integration and OAuth; hosted at nameremember.com; 0 stars; licence not stated; the page does not describe any recognition method. — [GitHub](https://github.com/tordsta/name-remember)

**Web apps that train names on stock faces (not personal contacts):**
- maxeleron/name-face-memory-training: "Simple web page application, for training memory on relation random face to name"; installable PWA with manifest + service worker, "Offline-ready app shell (PWA); face images need network"; uses generated faces and curated first-name datasets; local-only stats with JSON export/import; GPL-3.0; 0 stars; "Optional personal photo upload (local only)" is an unchecked roadmap item, i.e. not implemented. No hosted demo listed. — [GitHub](https://github.com/maxeleron/name-face-memory-training)
- Name Genius (namegeni.us) is "a free mobile web app" for remembering people's names and faces using spaced repetition; launched 2019 on Product Hunt (6 upvotes); the listing does not say whether users can upload their own photos. — [Product Hunt](https://www.producthunt.com/products/name-genius)
- FlashRecall is an AI flashcard app for iPhone/iPad with a browser practice tool at /flashcards; its blog says you can "Take a photo of someone or import from your camera roll" to make face flashcards and that it "works offline"; free to start with signup. It is primarily a native iOS app, not a PWA. — [FlashRecall blog](https://flashrecall.app/blog/face-flashcards)

**Things that look like web apps but are not:**
- namememory.netlify.app is a landing page for the native NameMemory app (KasamiWorks, Japan) for iOS and Android: stores names, photos, notes; SM-2 spaced repetition reminders; avatar builder instead of photo; data on device, "no accounts, analytics, or third-party trackers", AES-256 SQLCipher database; free up to 20 people, one-time PRO purchase; no browser version. — [namememory.netlify.app](https://namememory.netlify.app/)

**iPhone Safari PWA constraints relevant to a camera + offline app:**
- WebKit bug reports document getUserMedia failures specifically in home-screen (standalone) mode: "getUserMedia is not supported when launched from the home screen" (2019), "IOS 17.4.1 getUserMedia camera stream does not work in pwa on some devices" (2024, bug 273938), and "In PWA, HTML Video Element may be unable to play stream from getUserMedia()" (2023, bug 252465). — [WebKit bug 273938](https://bugs.webkit.org/show_bug.cgi?id=273938); [WebKit bug 252465 thread](https://lists.webkit.org/pipermail/webkit-unassigned/2023-May/1101465.html)
- Safari's 7-day cap on script-writable storage (2020) applies to Safari tabs; a 2021 WebKit bug was filed as "Service worker and storage deleted after 7 days on Web application added to Home Screen", and an Apple Developer Forums thread notes developers "cannot find documentation from Apple stating this one way or the other" for installed apps. — [Search Engine Land](https://searchengineland.com/what-safaris-7-day-cap-on-script-writeable-storage-means-for-pwa-developers-332519); [WebKit bug 232302](https://bugs.webkit.org/show_bug.cgi?id=232302); [Apple Developer Forums](https://developer.apple.com/forums/thread/710157)
- A third-party guide states that storage used in Safari is not shared with the home-screen instance of the same PWA ("data stored while using the PWA in Safari won't be accessible when the PWA is launched from the home screen, and vice versa"). — [MagicBell PWA iOS guide](https://www.magicbell.com/blog/pwa-ios-limitations-safari-support-complete-guide)
- A 2019 tutorial shows face-api.js (browser face detection) plus the Web Speech API inside a PWA, confirming the pattern is technically possible in a browser. — [totheroot.io tutorial](https://totheroot.io/article/tutorial-how-to-build-a-progressive-web-app-pwa-with-face-recognition-and-speech-recognition)

### Inferences
- Nothing in this category is "done well" on iPhone as a web app: the only two PWAs that store real people (geetman Faces, va3un people-memory) are hobby projects with 0–1 stars, no release, and (for va3un) explicitly unfinished.
- The safest capture path for an iPhone web app is `<input type="file" accept="image/*" capture>` (opens the native camera UI) rather than live getUserMedia inside a standalone PWA, given the WebKit bug history; this is my inference from the bug reports, not something a cited source states.
- The gap suggests opportunity: a PWA that does photo + spoken name + browse by date/category would have essentially no direct web competition, but must plan for iOS storage behaviour (test persistence; offer export/sync).

### Gaps
- Could not verify whether geetman "Faces" supports offline use or browse-by-date beyond its encounter timeline (README silent).
- No current WebKit status found for whether the standalone getUserMedia bugs are fixed on iOS 18/26.
- No Apple documentation found stating whether home-screen web apps are exempt from 7-day storage eviction.

## Key Question 2: What open-source projects exist, and how complete are they? Could one be adapted?

### Takeaway
Open-source "remember who I met" projects are all tiny (0–1 stars) and either unfinished or demo-grade; none has face recognition built in. The strongest adaptation paths are (a) fork geetman "Faces" (CC BY 4.0, already has photo/category/voice memo/timeline, needs a Supabase backend) or va3un "people-memory" (MIT, offline-first but mostly unimplemented), and (b) borrow components: vladmandic/human (3.4k stars, MIT) for in-browser face embeddings and matching against IndexedDB, or self-hosted photo managers Immich/PhotoPrism for server-side face clustering and naming.

### Cited Findings

**Dedicated people-memory repos (GitHub search results, Nov 2026):**
- geetman/Faces-People-Memory-App — JavaScript, 1 star, updated 2026-06-25, PWA, Supabase backend, CC BY 4.0 (details in KQ1). — [README](https://raw.githubusercontent.com/geetman/Faces-People-Memory-App/main/README.md)
- va3un/people-memory — TypeScript, 0 stars, pushed 2026-10-29, MIT, offline-first PWA with hosted demo; roadmap shows almost everything still planned. — [README](https://raw.githubusercontent.com/va3un/people-memory/main/README.md); [ROADMAP](https://raw.githubusercontent.com/va3un/people-memory/main/docs/ROADMAP.md)
- tordsta/name-remember — Next.js/Postgres/GCP example project with Stripe and Slack, 0 stars, live at nameremember.com, licence not stated. — [GitHub](https://github.com/tordsta/name-remember)
- maxeleron/name-face-memory-training — vanilla JS PWA trainer with generated faces, GPL-3.0, 0 stars, personal photo upload not implemented. — [GitHub](https://github.com/maxeleron/name-face-memory-training)
- Other hits from GitHub search (not inspected beyond metadata; all 0 stars): nonoyjuswa/People-Memory-App (Python, updated 2026-09-27), Mhlotshana/luminara-memory-vault-build (TypeScript, 2026-06-05), pranjuchakrapani90-collab/Total-Recall "Personal name recalling App" (HTML, updated 2026-11-08), DGempler/know-your-circle (Ruby, 2016, "learn and remember names & faces"), coolaj86/facecards "A face / name memory game" (JS, 2020, 1 star), atomysuper/face-name-quiz (TypeScript, 2026-03-25, 1 star). — GitHub search metadata (gh search repos, 2026-11-08)
- Searches for "who did I meet", "remember people met", "face tagging personal photos", "personal face database", "meet people photo name notes", "remember names app" returned no repositories. — GitHub search, 2026-11-08

**Reusable building blocks:**
- vladmandic/human: TypeScript library on TensorFlow.js for face, body, hand, iris and gesture analysis; 3.4k stars, 457 forks, MIT; default face detector BlazeFace, 468-point face mesh, face description model "HSE FaceRes"; browser demos include "Face Match" (descriptors and similarities against a known database) and "Face ID" (matches webcam input against faces stored in IndexedDB); backends WebGPU/WebGL/WASM/CPU; "Compatible with both desktop and mobile platforms". — [GitHub](https://github.com/vladmandic/human)
- Immich (self-hosted photos): run the Facial Recognition job, then review faces under Explore > People and assign names; each name then links matching photos across the library. PhotoPrism: face recognition on by default; open People, pick a cluster, name it; same-named clusters merge. Both are server-side, not browser-side. — [selfhosted-sh comparison](https://selfhosted-sh.pages.dev/immich-vs-photoprism-comparison); [elest.io comparison](https://blog.elest.io/immich-vs-photoprism-which-self-hosted-photo-manager-for-your-family/)
- Apple's Photos app "uses on-device analysis to recognize the faces of people in photos" and groups them into the People & Pets album; when you name a person "their name and face will appear in Photos across all your iCloud-enabled devices"; "Apple does not access your photos or videos". (Relevant as a no-code alternative: tag people in Photos and search by name.) — [Apple Photos privacy](https://www.apple.com/legal/privacy/data/en/photos/)

### Inferences
- None of the dedicated repos is a credible base for a product without substantial work; geetman "Faces" is the most feature-complete (photo, category, tags, voice memo, encounter timeline, search) but stores media as base64 in Supabase rows, which will not scale, and its passphrase model is not real auth.
- A realistic build-vs-adapt plan: write a new PWA, reuse the UX ideas from "Faces", use Dexie/IndexedDB locally (as va3un planned), and optionally add vladmandic/human for on-device "which of *my* saved people is this?" matching — a pattern whose demo already exists in that library.
- The "Faces" CC BY 4.0 licence permits commercial reuse with attribution; va3un is MIT; maxeleron is GPL-3.0 (copyleft), so the latter is less attractive for proprietary adaptation.

### Gaps
- Exact star counts/last-commit dates for tordsta and maxeleron were not shown on the rendered pages; GitHub API access was blocked in this session.
- No hosted demo or screenshots confirm geetman "Faces" works end-to-end on iPhone Safari.
- Did not find any open-source project that already combines personal face embeddings with a "people I met" diary.

## Key Question 3: Have 2024–2026 AI products (glasses, pendants, apps) shipped a real "remember this person's name" feature with a photo?

### Takeaway
No mainstream AI wearable has shipped a visual face-based "remember this person" feature as of November 2026. Meta built one ("Name Tag", surfaced in-app as "Connections… remember people they've met"), shipped it dormant inside the Meta AI app, and removed it in June 2026 after WIRED/EFF exposure, while denying the feature exists. Audio pendants (Limitless, Bee, Omi, Plaud) remember *conversations* and label speakers, not faces; Limitless was acquired by Meta in Dec 2025 and hardware sales stopped. The only face-based "who is this" demo was the unreleased Harvard I-XRAY hack (2024).

### Cited Findings

**Meta Ray-Ban / Meta AI app "Name Tag":**
- 13 Feb 2026: MacRumors, summarising the New York Times, reported Meta plans facial recognition for its Ray-Ban glasses "internally called 'Name Tag,' as soon as 2026", letting wearers "identify people and get information about them through Meta's AI assistant". Options under discussion: people the user knows through a Meta platform, or anyone with a public Instagram-type account; "Name Tag would not let users look up just anyone they encounter". An internal May 2025 document first planned a launch for attendees of a conference for the blind, then shifted to general release, and said "political tumult" made the timing good. Meta's statement: "still thinking through options and will take a thoughtful approach if and before we roll anything out." - 4 Jun 2026: EFF ("Move Fast, Surveil Things", Cooper Quintin) confirmed via static analysis that facial recognition code was present in Meta's app; the code "stores faceprints as 'a series of 2,048 numbers uniquely representing the positioning of a person's facial features'" and, once activated, would compare each new face the glasses see against the user's stored faceprints; another researcher added a face via debug mode and the glasses detected it. ### Inferences

- Audio pendants solve a neighbouring problem (what was said, by which speaker) and are not a substitute for a photo + name log; Whodat? (Android) is the closest shipped AI-era consumer app to the brief, but it is essentially unused (52 installs).

## Key Question 4: What are the legal/platform limits on adding face recognition to a personal app, and what is allowed?

### Takeaway
Apple's Vision framework offers face *detection*, landmarks and capture quality only — no identity matching — so any "who is this?" needs a third-party or custom model; the App Store guidelines do not ban face recognition outright but forbid using facial-mapping data for advertising/data mining, require consent, and steer authentication to LocalAuthentication. Illinois BIPA (private right of action, now per-person damages after the 2024 amendment), Texas/Washington/Colorado (AG-enforced) and EU GDPR Article 9 make *collecting faceprints of other people* legally hazardous for a company, whereas purely personal, on-device matching within the user's own photos is the model Apple Photos itself uses and the one the Dutch DPA says falls under GDPR's household exemption. Cross-referencing strangers against the open web (Clearview/PimEyes style) is the litigated, sanctioned zone.

### Cited Findings

**Apple Vision framework:**
- WWDC21 "Detect people, faces, and poses using Vision": "We currently offer face detection, face landmarks detection, and face capture quality detection." Face capture quality "is not designed to compare faces of different people." No identity recognition is mentioned. — [Apple WWDC21 session 10040](https://developer.apple.com/videos/play/wwdc2021/10040/)
- Apple's Photos privacy page: Photos "uses on-device analysis to recognize the faces of people in photos" into the People & Pets album; naming a person syncs "across all your iCloud-enabled devices"; "Apple does not access your photos or videos". (Apple reserves identity recognition for its own Photos app; third parties get detection only.) — [Apple](https://www.apple.com/legal/privacy/data/en/photos/)
- A 2017 Apple Developer Forums thread already concluded Vision "only provides face detection and landmark support rather than recognition of individual people." — [Apple Developer Forums](https://developer.apple.com/forums/thread/79961)

**App Store Review Guidelines (fetched 2026-11-08):**
- 2.5.13: "Apps using facial recognition for account authentication must use LocalAuthentication (and not ARKit or other facial recognition technology) where possible, and must use an alternate authentication method for users under 13 years old." — [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)
- 5.1.2(vi): "Data gathered from … depth and/or facial mapping tools (such as ARKit, Camera APIs, or Photo APIs) may not be used for marketing, advertising or use-based data mining, including by third parties." — [Apple](https://developer.apple.com/app-store/review/guidelines/)
- 5.1.2(i): "you may not use, transmit, or share someone's personal data without first obtaining their permission… You must clearly disclose where personal data will be shared with third parties, including with third-party AI, and obtain explicit permission before doing so." 5.1.1(iii) data minimisation: "Where possible, use the out-of-process picker or a share sheet rather than requesting full access to protected resources like Photos or Contacts." The word "biometric" does not appear in the first ~100k characters of the guidelines. — [Apple](https://developer.apple.com/app-store/review/guidelines/)
- Apple suspended Clearview AI's developer account for violating enterprise-program policies when it distributed its face-search app outside the App Store. — [TechRadar](https://www.techradar.com/news/apple-blocks-clearview-ai-facial-recognition-app-for-violating-app-store-policies)
- FaceTec's submission guide quotes Apple Developer Program License Agreement §3.3.52 as restricting "Face Data" use for authentication, advertising or marketing, and says face matching can be used "as long as your users explicitly agree that their Face Data can be used" (vendor source; verify against the current agreement). — [FaceTec](https://dev.facetec.com/technical-support-ios-sdk-guides-ios-app-store-submission-issues)

**Third-party face SDKs available for iOS:**
- Luxand FaceSDK: cross-platform face detection and recognition library for iOS among others; Luxand's own "Luxand Face Recognition" consumer app is on the App Store (evidence that recognition apps are not banned per se). — [Luxand](https://www.luxand.com/facesdk/documentation/); [App Store listing](https://apps.apple.com/jp/app/id666307566)

**US biometric privacy law:**
- Illinois BIPA amendment S.B. 2979 signed 2 Aug 2024: repeated collection of the same person's biometric data by the same method counts as one violation (per-person, not per-scan). On 1 Apr 2026 the Seventh Circuit (No. 25-2185) held the amendment applies retroactively to pending cases. — [Polsinelli](https://www.polsinelli.com/privacy-litigation/publications/bipa-amendment-limiting-damages-applies-retroactively); [Biometric Update](https://www.biometricupdate.com/202604/bipa-damage-limitation-applies-retroactively-to-pending-class-actions-court); [JD Supra on SB 2979](https://jdsupra.com/legalnews/illinois-governor-signs-the-first-1204943)
- Illinois is the only state with a private right of action; Texas (CUBI), Washington (RCW 19.375) and Colorado (CPA biometric amendments, effective 1 July 2025) are AG-enforced with per-violation penalties reported as $25,000 / $7,500 / $20,000 respectively. Texas AG's 2024 Meta settlement was $1.4B and Google's May 2025 settlement $1.375B. Sources disagree on how many states have dedicated biometric statutes (3, 4 or "23" when counting comprehensive privacy laws). — [privacyterms.io](https://privacyterms.io/biometric-privacy-laws-by-state-2026); [recordinglaw.com](https://www.recordinglaw.com/us-laws/data-privacy-laws/biometric-privacy-laws/); [stateofsurveillance guide](https://stateofsurveillance.org/guides/basic/23-states-biometric-privacy-laws/)
- Clearview AI: district court approved a nationwide BIPA class settlement (≈23% equity stake) on 20 Mar 2025; the Seventh Circuit vacated approval on 13 Jul 2026 (Sanders v. Clearview AI) over inadequate separate representation of the nationwide class vs state subclasses, remanding to the district court; the ruling did not find Clearview violated the law. — [Law360/MLex](https://www.law360.com/mlex/articles/2500414/clearview-ai-settlement-in-us-privacy-case-vacated-on-appeal); [ID Tech Wire](https://idtechwire.com/appeals-court-vacates-clearview-ai-biometric-privacy-settlement/); [Darrow on 2025 approval](https://www.darrow.ai/news/a-first-in-bipa-litigation-class-members-receive-equity-in-clearview-ai)
- Meta previously paid $650M to settle a BIPA suit and shut down Facebook photo face recognition (~2021). — [EFF](https://www.eff.org/deeplinks/2026/06/move-fast-surveil-things); [MacRumors](https://www.macrumors.com/2026/02/13/meta-facial-recognition-smart-glasses/)

**EU GDPR:**
- Dutch DPA guidance (May 2024): GDPR does not apply to facial recognition by individuals "for activities with a purely personal or household purpose", with conditions; the Article 9 ban on special-category data still applies where facial recognition is used to confirm identity outside that context, and the DPA's position is that facial recognition is "prohibited in most cases". French and Belgian DPAs take a similar view for biometric authentication where no third party accesses the data. — [A&O Shearman](https://www.aoshearman.com/en/insights/ao-shearman-on-data/netherlands-the-dutch-data-protection-authority-publishes-guidance-on-facial-recognition-may-2-2024); [Biometric Update](https://www.biometricupdate.com/202405/no-facial-recognition-in-supermarkets-says-dutch-data-watchdog); [Lexgo on Belgian DPA](https://www.lexgo.be/en/news-and-articles/11396-the-bdpa-s-recommendation-on-processing-of-biometric-data)
- GDPR Recital 51: photographs are not systematically special-category data; they become biometric data only when processed "through a specific technical means allowing the unique identification or authentication". — [VeraSafe](https://verasafe.com/blog/gdpr-and-photographs-understanding-special-categories-of-personal-data/)

### Inferences
- What is clearly allowed: an app where the *user* photographs people they meet and types/speaks a name, with photos stored as ordinary images. Face *detection* (Vision) for auto-cropping is uncontroversial. On-device *matching among the user's own saved people*, with no server upload and no third-party lookup, mirrors Apple Photos and sits inside the household exemption in the EU; the main US risk is that the *subjects* (the people photographed) never consented under BIPA — a company doing the processing on its servers for Illinois users would be exposed, whereas purely on-device processing by the individual is a much weaker target (inference; no court has ruled on this exact pattern).
- What is not allowed or is very risky: any "who is this stranger?" lookup against the web, social profiles or a shared database (Clearview, PimEyes/I-XRAY, Meta Name Tag option 2); using face data for ads/analytics (Apple 5.1.2(vi)); sending face data to third-party AI without explicit disclosure/consent (5.1.2(i)).
- Practical product consequence: a consumer app should default to *no* automatic face identification, make any on-device matching an opt-in that only ever searches the user's own saved entries, keep embeddings on device, and avoid Illinois-specific server processing of faceprints.

### Gaps
- No Apple document found that explicitly says third-party face *identification* SDKs are acceptable; acceptability is inferred from Luxand's listed app and vendors' submission guides.
- No case law found on BIPA applicability to an individual consumer's on-device processing of a third party's face; law-firm summaries address businesses.
- Did not read the Seventh Circuit opinion or Dutch DPA guidance in the original.
